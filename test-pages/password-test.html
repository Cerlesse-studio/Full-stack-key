密码记录功能测试台

用于验证 Chrome 扩展的「自动检测登录表单 → 弹出保存提示 → 写入保险库」全链路。页面不会真实提交任何数据。

扩展检测中…

使用前提：先在 chrome://extensions 加载 extension/ 目录，并在扩展选项页填好服务端地址与 API Key。 本页以 http://localhost:4200 访问（file:// 需额外勾选「允许访问文件网址」）。

① 标准登录

最常见

带完整 autocomplete 语义，用户名靠属性即可识别。提交 / 回车 / 点按钮都应弹出保存提示。

回车也生效

② 邮箱登录

type=email

用户名字段是 type="email" 且无任何 name/id 提示，扩展应按输入类型识别。

③ 无语义提示

考验兜底

所有字段都不含 user/email/login 等关键字，扩展应回退为「密码框前一个输入框」。

④ 注册（含确认密码）

双密码框

两个密码框时，扩展只取第一个作为密码，第二个会被忽略 —— 这是当前的已知行为。

⑤ 修改密码

三密码框

当前密码 / 新密码 / 确认新密码。注意保存提示里出现的是旧密码，属预期。

⑥ 回车触发（无 form）

captureSingle

密码框不在任何 <form> 内，直接在密码框按回车也应弹出保存提示。

在密码框按 Enter

⑦ 延迟渲染表单

SPA 场景

表单在页面加载后才插入。扩展若未重新扫描，这里不会弹出提示 —— 正好暴露该缺口。

⑧ iframe 内表单

跨文档边界

内容脚本默认不注入 iframe 文档，此处表单通常不会触发保存提示，属预期行为。

⑨ 多密码框密集区

下拉定位

多个密码框用于观察扩展的下拉提示是否逐个正确定位，以及是否会互相串位。

逐个点击以上密码框，应各自出现可填充的下拉。

⑩ 右键菜单

background

在本页任意空白处右键，应出现扩展菜单项（保存当前页面密码 / 忽略此网站）。

若没有：确认 manifest.json 的 contextMenus 权限，并检查后台 service worker 是否报错。
